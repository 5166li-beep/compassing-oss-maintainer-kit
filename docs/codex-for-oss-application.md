# Codex for Open Source application notes

This document is an internal checklist for preparing a truthful application.
It is not a promise of acceptance and must not be used to inflate project
metrics.

## Before applying

- Make the repository public and verify that the applicant has the stated
  maintainer permissions.
- Keep a real history of releases, pull-request review, issue triage, or other
  ongoing maintenance.
- Record verifiable GitHub stars, package downloads, or an evidence-based
  explanation of ecosystem importance. Do not estimate these numbers as facts.
- Use the ChatGPT account email requested by the form and the correct OpenAI
  organization ID.
- Remove secrets, personal identity documents, customer data, and confidential
  business plans from the repository and application.

## Honest project description

Maintainer Evidence is a small, open-source, local-first tool that turns Git
history and repository hygiene signals into a reviewable JSON/Markdown evidence
pack. It helps maintainers document real work without sharing credentials or
granting a service access to private repositories. The included read-only GitHub
Action keeps the evidence artifact current for pull-request and release
workflows.

The application should state the actual repository age, usage, stars, downloads,
and maintainer role at the time of submission. If the project is early, say so
and explain the concrete ecosystem problem it addresses; never imply adoption
that has not happened.
